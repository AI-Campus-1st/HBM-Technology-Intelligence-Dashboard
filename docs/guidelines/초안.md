## 1. 프로젝트 한눈에 보기

### 1.1 기획 배경

반도체 분야에서는 HBM, 차세대 DRAM, 첨단 패키징 등 기술 관련 보도가 지속적으로 발생한다. 뉴스만으로는 어떤 이슈가 실제로 두드러지는지, SK하이닉스의 공개된 연구개발·투자 활동과 어떤 연관이 있는지 판단하기 어렵다.

**우리는 뉴스의 기술 이슈 변화 → 급증 시점 탐지 → 공시 근거 확인 → 전략 검토용 요약**이라는 분석 흐름을 구현한다.

### 1.2 사용자(Persona)

| 구분 | 내용 |
| --- | --- |
| 핵심 사용자 | SK하이닉스 기술전략팀의 산업·경쟁 동향 분석 담당자 *(가상 페르소나)* |
| 업무 상황 | 외부 기술 동향을 모니터링하고 R&D 전략 검토를 위한 사전 분석 자료 작성 |
| 해결할 문제 | 기사량이 많고 중복 보도가 많아 중요한 변화의 시점과 근거 확인이 어려움 |
| 필요한 결과 | 기술별 관심도 변화, 급증 사건, 공개된 기업 활동, 근거 문서, 불확실성 |
| 사용 범위 | **공개자료 기반 기술 인텔리전스**. 사내 R&D 투자 의사결정 자체를 대체하지 않음 |

### 1.3 핵심 질문 — 추천 확정안

> HBM 중심의 AI 반도체 기술 경쟁에서 SK하이닉스가 주목해야 할 기술적 기회와 위험은 무엇인가?
> 

**보조 질문**

1. HBM 기술 이슈가 언제 급증했는가?
2. 급증 시점에 해당하는 뉴스 사건은 무엇이며, 재배포·중복 영향은 얼마나 되는가?
3. 관련 SK하이닉스 공시에서 확인할 수 있는 R&D 활동·투자 정보는 무엇이고, 확인할 수 없는 부분은 무엇인가?

### 1.4 최종 목표

> 최근 3년간 반도체 산업 뉴스와 SK하이닉스 DART 공시를 통합 분석하여 HBM 기술 이슈의 변화와 급증 시점을 탐지하고, 공개된 연구개발 활동 및 투자 정보와 비교한다. 이를 통해 **근거와 한계를 명시하는 기술전략 검토용 AI 대시보드**를 구축한다.
> 

**성공 기준:** 사용자가 주요 기술 이슈의 변화, 변화가 나타난 이유, 연결 가능한 공시 근거 및 추가 확인이 필요한 사항을 한 화면 흐름에서 파악할 수 있다.

## 2. 과제 가이드의 필수 요구사항과 우리의 추가 제안

### 2.1 필수 요구사항 — 과제 가이드 기준

- [ ]  DART OpenAPI로 SK하이닉스 공시 수집 및 뉴스와 함께 DB 저장
- [ ]  기사량·공시 건수·이슈 급증 시점을 포함한 EDA와 시계열 분석
- [ ]  LLM을 이용한 감성 분류·핵심 이슈 추출
- [ ]  LLM 분류 결과의 **표본 수동 검수** 및 정확도 기록
- [ ]  공시 문서 기반 RAG 질의응답 기능
- [ ]  Q&A 답변마다 공시명·제출일·링크 등 출처 표시
- [ ]  Streamlit에서 이슈 분석과 공시 Q&A 통합
- [ ]  대시보드 상단에 의사결정 관점의 결론 제시
- [ ]  코드 저장소, 리포트, 발표 제출

### 2.2 포트폴리오 경쟁력을 위한 제안 — 추가 권장

- [ ]  RAG 사용 시, SQL TO TEXT기법 활용
- [ ]  기술별 기사 **절대량 + 전체 대비 비중**을 함께 분석
- [ ]  뉴스 중복률, 결측률, 주제 관련성 등 데이터 품질 지표 기록
- [ ]  SQL 분석 쿼리 3~5개를 별도 보관·설명
- [ ]  기술 기회/위험/경쟁 심화/판단 유보 등 **기업 관점의 분류** 추가
- [ ]  대표 기술 이슈 2~3개에 대해 뉴스와 공시의 연결 근거 심층 검토
- [ ]  모델 성능은 단순 일치율뿐 아니라 클래스별 Precision·Recall·F1 및 오류 사례로 설명 *(표본 수가 허용할 때)*
- [ ]  발표에서 **사실 / 해석 / 한계**를 명확히 구분

> **주의:** 추가 제안은 필수 평가 기준이 아니다. 7일 일정에서는 필수 기능 완성이 먼저다.

## 3. 포트폴리오 관점의 비판적 점검

| 문제 | 왜 위험한가? | 개선 방안 |
| --- | --- | --- |
| **사용자와 데이터의 불일치** | 실제 R&D 전략 의사결정에는 내부 원가·수율·기술 성숙도 등의 데이터가 필요한데 공개 데이터만 확보됨 | 사용자를 ‘외부 기술 동향 분석 담당자’로 구체화 |
| **기사량 = 기술 중요도라는 착각** | 중복 기사·매체 편향·특정 사건으로 기사 수가 폭증할 수 있음 | 중복 제거, 전체 대비 비중, 급증 사건 원문 점검 |
| **R&D 총액을 기술별 투자로 오인** | 공시상 총 연구개발비가 늘어도 HBM에 투입된 금액인지는 별도로 확인해야 함 | 기업 전체 수치와 기술별 언급을 구분; 인과관계 주장 금지 |
| **일반 감성분석의 한계** | 경쟁사에 부정적인 사건이 SK하이닉스에 유리할 수 있음 | 감성분석은 필수 수행하되 기업 관점 영향 분류를 보조 지표로 사용 |
| **SQL 활용 증거 부족** | ‘DB에 저장했다’는 사실만으로 데이터 분석 역량을 충분히 보여주기 어려움 | SQL 집계·중복 제거·기간 비교 쿼리 기록 |
| **AI 기능 중심의 평범한 결과물** | 뉴스 요약 + 챗봇만으로는 분석적 기여가 약함 | 데이터 검증 → 변화 탐지 → 공시 근거 → 판단의 한계를 중심 스토리로 구성 |

**포트폴리오의 핵심 메시지**

“LLM과 Streamlit을 사용했다”보다 **“공개 데이터의 한계를 이해하고, 검증 가능한 기술 이슈를 찾아 근거와 함께 설명했다”**를 보여준다.

## 4. 데이터 및 분석 범위

### 4.1 데이터 출처

| 데이터 | 확보 방법 | 주요 용도 | 검증 사항 |
| --- | --- | --- | --- |
| 반도체 뉴스 | 교육 과정에서 제공되는 최근 3년 뉴스 데이터 | 기술 이슈 시계열·이슈 추출·감성 분류 | 중복, 날짜, 키워드 관련도, 본문/제목 유무 |
| SK하이닉스 공시 | DART OpenAPI(`corpCode.xml`, `list.json`, 공시 원문) | 공개 R&D 활동 및 투자 근거 확인, RAG | 공시 유형, 원문 접근, 제출일, 문서 단위 |
| 추가 뉴스 원문 *(선택)* | 출처별 원문 확보 | 급증 사건 재확인 | 수집 가능 범위, 출처, 이용 조건 |

**가이드에 포함된 반도체 수집 키워드:** `반도체 수출 통제`, `반도체 세제 혜택`, `반도체 R&D`, `반도체 밸류체인`, `반도체 원자재`.

> **핵심 사전 점검:** 제공 뉴스가 직접적으로 `HBM`, `첨단 패키징`, `차세대 DRAM`을 충분히 포함하는지는 아직 확인되지 않았다. 수집된 기사 분포에 따라 기술 세부 주제를 조정한다.
> 

### 4.2 추천 분석 대상

- **우선 후보:** HBM 및 차세대 고대역폭 메모리
- **보조 후보:** 첨단 패키징 및 적층 기술
- **보조 후보:** 차세대 DRAM
- **범위 조정 규칙:** 기사 수·관련성이 부족한 분야는 제외하거나 ‘반도체 R&D 전반’으로 묶는다.

### 4.3 추천 지표

| 영역 | 지표 | 해석 유의점 |
| --- | --- | --- |
| 뉴스 규모 | 일별·월별 기사 수 | 중복 제거 전후 수치 병기 |
| 관심도 | 기술별 기사 수 / 같은 기간 전체 분석 기사 수 | 뉴스 구성의 변화를 기술 중요도와 동일시하지 않음 |
| 변화 | 전월 대비 기사 비중 변화, 급증 시점 | 관측 기간·표본 수가 적으면 과장 금지 |
| 정서 | 기술별 긍정/중립/부정 비율 | 기업 영향과 동일하지 않음 |
| 공시 | 기간별 공시 건수, 연구개발비 등 확인 가능 항목 | 공시 유형 및 회계 기준 통일 |
| 근거 | 이슈별 연관 공시와 문서 출처 | 단순 시점 일치만으로 인과관계 주장 금지 |

### 4.4 데이터 모델 초안 — Day 1 협의

- `news`: `news_id`, `published_at`, `title`, `body`(있을 때), `source`, `url`, `raw_keyword`, `cleaned_title`, `duplicate_group_id`
- `disclosures`: `rcept_no`, `corp_code`, `report_nm`, `rcept_dt`, `report_type`, `url`, `text_status`
- `news_analysis`: `news_id`, `technology_tag`, `sentiment`, `impact_tag`(선택), `model_version`, `review_status`
- `disclosure_chunks`: `chunk_id`, `rcept_no`, `chunk_text`, `page_or_section`, `embedding_ref`
- `issue_evidence`: `issue_id`, `news_id`, `rcept_no`, `match_type`, `verification_status`

`issue_evidence`의 자동 연결은 **후보 연결**일 뿐, 검증된 사실로 표시하지 않는다.

## 5. 핵심 분석 흐름

### A. 기술 이슈 변화 탐지

1. 기사 중복·결측·관련성 점검
2. 기술 태그 분류(HBM, 패키징, DRAM 등)
3. 월별 기사 수와 전체 대비 기술별 비중 계산
4. 급증 구간 식별
5. 급증의 원인이 된 대표 기사/사건 검토

**산출물:** 기술별 시계열 차트 + 대표 급증 시점 2~3개 + 사건 요약.

### B. 공개된 기업 활동과 연계

1. 해당 기간의 SK하이닉스 공시 수집
2. 연구개발 현황, 투자, 사업 및 제품 관련 문구 추출
3. 기술 이슈와 연결 가능한 공시 검토
4. 공시에서 **확인된 사실 / 뉴스상 사건 / 분석 해석**을 별도 필드로 표기

**산출물:** 이슈별 근거 문서 카드(공시명·제출일·링크·관련 문구).

### C. AI 분석 및 공시 Q&A

1. LLM으로 뉴스 감성 분류와 핵심 이슈 추출
2. 표본 직접 검수 및 오류 유형 분석
3. 공시 청킹·임베딩·검색 파이프라인 구성
4. RAG 답변 생성 시 공시 출처 함께 표시
5. 근거 없는 질의에는 **‘공개 공시에서 확인되지 않음’** 응답

**산출물:** 성능 검증 결과 + 출처를 가진 공시 질의응답.

### 분석 사례 작성 템플릿

- **발견한 변화:** (예: 특정 기술 관련 뉴스 비중 급증)
- **데이터 근거:** 기간, 기사 수, 중복 제거 결과, 비중 변화
- **사건 설명:** 대표 기사 1~3개와 출처
- **기업 공개 근거:** 관련 공시명, 제출일, 핵심 구절
- **해석:** 기술전략 관점의 의미 *가능성 중심으로 기술*
- **한계:** 공시로 확인되지 않은 사항, 데이터 편향
- **후속 확인사항:** 추가 조사할 기술·경쟁·공급망 이슈

## 6. Streamlit 대시보드 권장 구조

### 상단 — 한눈에 보는 결론

- 분석 기간, 대상 기술, 주요 변화 1~2문장
- 가장 두드러진 기술 이슈와 근거 링크
- 데이터 커버리지/분류 신뢰도 안내

### 탭 1. 기술 이슈 모니터링

- 기간·기술 카테고리 필터
- 기술별 기사량 및 비중 추이
- 이슈 급증 시점 표시
- 급증 시점의 대표 기사 목록

### 탭 2. SK하이닉스 공시 근거

- 관련 공시 목록 및 유형별 분포
- 공개 연구개발·투자 정보 비교 *(확인 가능한 항목만)*
- 선택 이슈별 근거 공시 링크 및 관련 문구
- 사실/해석/한계 구분

### 탭 3. 공시 Q&A

- 예시 질문 및 사용자 질문 입력
- 출처(공시명·제출일·링크) 제공

### 9.3 해석 주의사항

1. **기업 전체 R&D 지출액 ≠ HBM 등 개별 기술 투자액.**
2. **기사량 증가 ≠ 기술 중요도 또는 사업성과 증가.**
3. **동일 시점의 뉴스·공시 존재 ≠ 두 사건의 인과관계.**
4. **뉴스 감성 ≠ SK하이닉스의 사업 영향.**
5. 비공개 사내 연구개발 데이터가 없으므로 실제 투자 최적화는 분석 범위 밖이다.
