## 1. 프로젝트 한눈에 보기

### 1.1 기획 배경

AI 반도체 수요 확대로 HBM이 메모리 업계의 핵심 경쟁 축이 되었다. SK하이닉스와 삼성전자에 대한 HBM 보도는 많지만 중복·재배포가 많아, 어떤 시점에 무엇이 변했는지, 그 변화가 각 기업의 공개된 연구개발·투자 활동과 어떻게 연결되는지 판단하기 어렵다.

**우리는 HBM 이슈 비중 변화 → 급증 시점 탐지 → 기업별(SK하이닉스·삼성전자) 보도·감성 비교 → 공시 근거 확인**이라는 분석 흐름을 구현한다.

### 1.2 사용자(Persona)

| 구분 | 내용 |
| --- | --- |
| 핵심 사용자 | 증권사 반도체 담당 애널리스트 *(가상 페르소나)* |
| 업무 상황 | 메모리 업체 실적·전략 리포트 작성 전, HBM 경쟁 구도의 변화와 근거 자료를 정리 |
| 해결할 문제 | 기사가 많고 중복 보도가 많아 "언제, 왜, 누구에게 유리하게" 이슈가 바뀌었는지와 공시 근거를 찾기 어려움 |
| 필요한 결과 | HBM 이슈 비중 추이, 급증 사건, 기업별 보도·감성 비교, 공시상 확인 사실, 확인 불가 항목 |
| 사용 범위 | **공개자료 기반 기술 인텔리전스**. 투자 의견·목표주가를 제시하지 않음 |

**페르소나 선정 근거 (v1.1)**

| 후보 | 데이터 적합도 | 판단 |
| --- | --- | --- |
| 반도체 담당 애널리스트 | 뉴스 + DART 공시 + 경쟁사 비교가 실제 업무 흐름과 일치 | **채택** |
| 기관투자자 | 주가·밸류에이션 데이터가 필요하나 범위 밖. 애널리스트 산출물의 소비자에 가까움 | 리포트에서 확장 사용자로 언급 |
| 협력사 전략기획 담당자 | 고객사별 발주·공급 데이터가 핵심이나 뉴스·공시로는 간접 확인만 가능 | 리포트에서 확장 사용자로 언급 |

> 세 페르소나를 동시에 두지 않는다. 가이드의 "상단 의사결정 결론"은 한 명의 의사결정을 전제로 하며, 7일 일정에서 사용자별 화면을 따로 만들 수 없다.

### 1.3 핵심 질문 — 추천 확정안

> HBM 경쟁에서 SK하이닉스와 삼성전자에 대한 시장의 관심과 이슈는 시기별로 어떻게 달라졌으며, 공시로 확인되는 대응과 애널리스트가 추가로 확인해야 할 기회·위험 신호는 무엇인가?
>

**보조 질문**

1. HBM 관련 보도 **비중**은 언제 급증하고 둔화했는가? 급증 시점의 대표 사건은 무엇인가?
2. 같은 기간 SK하이닉스와 삼성전자의 HBM 보도 점유율과 감성은 어떻게 달랐는가?
3. 두 기업의 공시에서 확인되는 R&D 활동·투자·제품 정보는 무엇이고, 확인할 수 없는 부분은 무엇인가?

### 1.4 최종 목표

> 최근 3년(2023-10-19 ~ 2026-10-19) 반도체 뉴스와 SK하이닉스·삼성전자 DART 공시를 통합 분석하여 HBM 이슈의 비중 변화와 급증 시점을 탐지하고, 기업별 보도·감성 차이와 공시 근거를 비교한다. 이를 통해 **근거와 한계를 명시하는 애널리스트용 기술 인텔리전스 대시보드**를 구축한다.
>

**성공 기준:** 사용자가 HBM 이슈의 변화, 변화가 나타난 이유, 기업별 차이, 연결 가능한 공시 근거 및 추가 확인이 필요한 사항을 한 화면 흐름에서 파악할 수 있다.

**상단 결론 문장 형식 (v1.1 추가)** — Day 6에 실측값으로 채운다. *아래는 형식 예시이며 분석 결과가 아니다.*

> "HBM 보도 비중은 [기간]에 [N]%로 정점을 찍은 뒤 [추세]. 같은 기간 SK하이닉스 대비 삼성전자 보도 점유는 [변화]했고, 부정 보도 비중은 [기업]이 높았다. [기업]의 [공시명, 제출일]에서 [확인된 사실]이 확인된다. 단, 기술별 투자액은 공시로 확인할 수 없다."

## 2. 과제 가이드의 필수 요구사항과 우리의 추가 제안

### 2.1 필수 요구사항 — 과제 가이드 기준

- [ ]  DART OpenAPI로 SK하이닉스·삼성전자 공시 수집 및 뉴스와 함께 DB 저장
- [ ]  기사량·공시 건수·이슈 급증 시점을 포함한 EDA와 시계열 분석
- [ ]  LLM을 이용한 감성 분류·핵심 이슈 추출
- [ ]  LLM 분류 결과의 **표본 수동 검수** 및 정확도 기록
- [ ]  공시 문서 기반 RAG 질의응답 기능
- [ ]  Q&A 답변마다 공시명·제출일·링크 등 출처 표시
- [ ]  Streamlit에서 이슈 분석과 공시 Q&A 통합, 필터(기간·기업·카테고리)가 모든 차트에 반영
- [ ]  대시보드 상단에 의사결정 관점의 결론 제시
- [ ]  코드 저장소, 리포트, 발표 제출

> 삼성전자 추가로 가이드의 **'기업' 필터가 의미를 갖게 되었다.** v1.2: 반도체 묶음은 가이드의 이슈 카테고리 키워드로 수집되어 **'카테고리' 필터를 그대로 쓸 수 있다.** 기술 태그(HBM 등)는 보조 필터로 둔다.

### 2.2 포트폴리오 경쟁력을 위한 제안 — 추가 권장

- [ ]  기술별 기사 **절대량 + 전체 대비 비중**을 함께 분석 *(§4.2 점검 결과가 필요성을 입증)*
- [ ]  **기업별 HBM 보도 점유·감성 비교** *(v1.1 신규)*
- [ ]  뉴스 중복률, 결측률, 주제 관련성 등 데이터 품질 지표 기록
- [ ]  SQL 분석 쿼리 3~5개를 별도 보관·설명
- [ ]  대표 기술 이슈 2~3개에 대해 뉴스와 공시의 연결 근거 심층 검토
- [ ]  모델 성능은 단순 일치율뿐 아니라 클래스별 Precision·Recall·F1 및 오류 사례로 설명 *(표본 수가 허용할 때)*
- [ ]  발표에서 **사실 / 해석 / 한계**를 명확히 구분
- [ ]  ~~RAG 사용 시, SQL TO TEXT기법 활용~~ → **Text-to-SQL로 용어 정정, P2로 강등.** 공시 RAG와 별개 기능이고 읽기 전용 제한·잘못된 쿼리 처리 비용이 큼. SQL 역량은 직접 작성한 쿼리로 보여준다.

> **주의:** 추가 제안은 필수 평가 기준이 아니다. 7일 일정에서는 필수 기능 완성이 먼저다.

## 3. 포트폴리오 관점의 비판적 점검

| 문제 | 왜 위험한가? | 개선 방안 |
| --- | --- | --- |
| **사용자와 데이터의 불일치** | 사내 전략 담당자는 공개 뉴스보다 좋은 내부 정보를 가짐 | *(v1.1 해결)* 공개 데이터가 자연스러운 **애널리스트**로 사용자 변경 |
| **기사량 = 기술 중요도라는 착각** | 분기별 전체 기사가 310~1,132건으로 크게 변동(2025Q1 최대). 절대량은 수집량 변동을 그대로 반영 | 중복 제거 후 **월별 비중**으로 판단, 급증 사건 원문 점검 |
| **HBM이 정책 기사에 묶여 수집됨** *(v1.2)* | HBM 제목 기사 205건 중 90건이 `반도체 수출 통제` 키워드로 수집됨. HBM 이슈가 규제 사건 위주로 보일 수 있음 | 카테고리별로 HBM 비중을 나눠 보고, 해석 시 수집 키워드 구성을 명시 |
| **표본 규모 축소** *(v1.2)* | 뉴스가 12만 건 → 7,177건으로 줄어 HBM 제목 기사는 분기당 1~46건 | 월별 집계, 급증 판단에 최소 기사 수 조건 검토, 수치보다 사례 중심 설명 |
| **'경쟁' 분석인데 경쟁사 데이터 없음** | 단일 기업으로는 경쟁 구도를 설명할 수 없음 | *(v1.1 해결)* 삼성전자 공시·뉴스 비교 추가 |
| **삼성전자와의 수치 비교 왜곡** | 삼성전자는 DX(모바일·가전)와 DS(반도체)가 함께 있어 회사 전체 R&D를 SK하이닉스와 직접 비교 불가 | 회사 전체 수치 비교 금지, 부문별로 공시된 항목만 사용 |
| **R&D 총액을 기술별 투자로 오인** | 총 연구개발비가 늘어도 HBM 투입액인지는 확인 불가 | 기업 전체 수치와 기술별 언급을 구분; 인과관계 주장 금지 |
| **일반 감성분석의 한계** | 경쟁사의 악재가 다른 기업에 호재일 수 있고, 한 기사에 두 기업이 함께 등장 | **기업별 감성 라벨**(SK하이닉스 관점 / 삼성전자 관점)로 분류 |
| **태깅 오류가 분석 전체를 무너뜨림** | 급증 분석은 HBM 관련 기사 판정에 의존하는데 v1.0은 감성만 검수 | 기술·기업 태깅을 **감성보다 먼저** 표본 검수 |
| **뉴스·공시 시간 단위 불일치** | 뉴스 급증은 월 단위, 정기보고서는 분기 단위라 자동 연결이 약함 | 자동 연결은 후보로만 표시, 급증 사례 2~3개는 수동 심층 연결 |
| **SQL 활용 증거 부족** | 'DB에 저장했다'는 사실만으로 분석 역량을 보여주기 어려움 | SQL 집계·중복 제거·기간 비교 쿼리 기록 |
| **AI 기능 중심의 평범한 결과물** | 뉴스 요약 + 챗봇만으로는 분석적 기여가 약함 | 데이터 검증 → 비중 변화 탐지 → 기업 비교 → 공시 근거 → 판단의 한계를 중심 스토리로 구성 |

**포트폴리오의 핵심 메시지**

"LLM과 Streamlit을 사용했다"보다 **"공개 데이터의 한계를 이해하고, 검증 가능한 기술 이슈를 찾아 근거와 함께 설명했다"**를 보여준다.

- `news`: `news_id`, `published_at`, `title`, `content`, `keyword`, `media`, `category`, `url`, `is_duplicate`, `dup_group_id` — `category`는 수집 키워드에서 변환해 채운다 (v1.2)

`issue_evidence`의 자동 연결은 **후보 연결**일 뿐, 검증된 사실로 표시하지 않는다.

## 5. 핵심 분석 흐름

### A. 기술 이슈 변화 탐지

1. 기사 중복·결측 점검 및 분석 기간 필터링
2. 정규표현식으로 관련도·기술·기업 태깅
3. **태깅 표본 검수** — 관련도 등급별 30건씩 수동 판정, 정밀도 기록. v1.1 데이터 1차 결과(HBM 핵심 0.97 / 관련 0.53 / 언급 0.00, Claude 1차 판정)는 참고용이며 **04 데이터로 재검수**한다
4. 월별 기사 수와 전체 대비 HBM 비중 계산 (카테고리별 포함)
5. 급증 구간 식별 (§4.3 기준)
6. 급증의 원인이 된 대표 기사/사건 검토

**산출물:** HBM 절대량·비중 시계열 차트 + 대표 급증 구간 2~3개 + 사건 요약.

### B. 공개된 기업 활동과 연계

1. 분석 기간의 SK하이닉스·삼성전자 공시 수집
   - 우선순위: 정기보고서('연구개발 활동', '사업의 내용') → 주요사항보고서(시설투자 등) → 거래소 공시(공급계약 등, 수집 가능 범위 확인)
2. 연구개발 현황, 투자, 사업 및 제품 관련 문구 추출
3. 기술 이슈와 연결 가능한 공시 검토
4. 공시에서 **확인된 사실 / 뉴스상 사건 / 분석 해석**을 별도 필드로 표기

**산출물:** 이슈별·기업별 근거 문서 카드(공시명·제출일·링크·관련 문구).

### C. AI 분석 및 공시 Q&A

1. LLM으로 **기업별 감성**(SK하이닉스 관점 / 삼성전자 관점)과 핵심 이슈 추출
   - 분류 대상은 분석 기간 내 HBM '핵심+관련' 기사로 한정 (현재 규칙 기준 약 1,100건, '관련' 기준 확정 후 Day 3에 건수·비용 확정)
   - 출력: `{"skh": "...", "sec": "...", "tech_tag": "...", "issue_keywords": [...]}`
2. 표본 직접 검수(100건 내외, 분기·기업 층화 추출), 교차 검수 20~30건, 오류 유형 분석
3. 두 기업 공시 청킹·임베딩·검색 파이프라인 구성 (기업 메타데이터 필터 지원)
4. RAG 답변 생성 시 공시 출처 함께 표시
5. 근거 없는 질의에는 **'공개 공시에서 확인되지 않음'** 응답

**기업별 감성 라벨 정의 (v1.1 추가)**

| 라벨 | 정의 (해당 기업의 HBM 사업 관점) | 예 |
| --- | --- | --- |
| 긍정 | 해당 기업에 유리한 사건·평가 | 고객사 인증 통과, 공급 확대 |
| 부정 | 해당 기업에 불리한 사건·평가 | 인증 지연, 수율 문제 |
| 중립 | 사실 전달 위주, 유불리 판단 불가 | 일정 발표, 업계 일반 동향 |
| 해당없음 | 기사에 해당 기업이 등장하지 않음 | — |

**산출물:** 태깅·감성 검증 결과 + 출처를 가진 공시 질의응답.

### 분석 사례 작성 템플릿

- **발견한 변화:** (예: HBM 관련 뉴스 비중 급증)
- **데이터 근거:** 기간, 기사 수, 중복 제거 결과, 비중 변화
- **기업별 차이:** SK하이닉스·삼성전자 보도 점유와 감성
- **사건 설명:** 대표 기사 1~3개와 출처
- **기업 공개 근거:** 관련 공시명, 제출일, 핵심 구절
- **해석:** 애널리스트 관점의 의미 *가능성 중심으로 기술*
- **한계:** 공시로 확인되지 않은 사항, 데이터 편향
- **후속 확인사항:** 추가 조사할 기술·경쟁·공급망 이슈

### 9.2 AI/검색 검증

- [ ]  기업별 감성 라벨 정의와 프롬프트 버전이 저장되어 있는가?
- [ ]  검수 샘플 수·추출 방법·교차 검수 일치율을 기록했는가? *(권장: 100건 내외)*
- [ ]  불균형 클래스에서 정확도만 제시하지 않는가?
- [ ]  RAG 답변의 출처가 실제 문서 내용과 일치하는가?
- [ ]  출처가 부족한 질문에서 답변을 유보하는가?

### 9.3 해석 주의사항

1. **기업 전체 R&D 지출액 ≠ HBM 등 개별 기술 투자액.** 사업 구조가 다른 삼성전자와 전체 수치를 직접 비교하지 않는다.
2. **기사량 증가 ≠ 관심 증가.** 분기별 수집량 변동이 크므로 비중으로 판단한다.
3. **보도 점유·감성 ≠ 실제 시장 점유율·사업 성과.**
4. **동일 시점의 뉴스·공시 존재 ≠ 두 사건의 인과관계.**
5. 투자 의견·목표주가는 분석 범위 밖이다.

## 10. 발표 스토리라인 및 포트폴리오 문장

### 권장 발표 흐름

1. **문제:** HBM 보도는 많지만 언제·누구에게·왜 이슈가 바뀌었는지와 공시 근거가 흩어져 있다.
2. **사용자:** 메모리 업체 리포트를 준비하는 반도체 담당 애널리스트.
3. **데이터:** 반도체 뉴스 7,177건(3개 이슈 카테고리) 중 HBM 기사 + 두 기업 DART 공시, 수집·정제·품질 검증.
4. **분석:** 절대량이 아닌 비중으로 본 HBM 이슈 변화·급증 구간, 기업별 보도·감성 비교, 분류 성능 확인.
5. **근거:** 급증 사건에 대한 두 기업의 공개된 활동·공시 검색.
6. **결과:** 대표 인사이트 2~3개, 불확실성, 추가 검토사항.
7. **회고:** 데이터 및 LLM 한계와 개선 방향.

### 포트폴리오 한 줄 설명 (초안)

> 반도체 뉴스와 SK하이닉스·삼성전자 공시를 통합해 HBM 이슈의 비중 변화와 급증 시점을 탐지하고, 기업별 보도·감성 비교와 근거 기반 RAG를 제공하는 애널리스트용 기술 인텔리전스 대시보드를 개발했다.
>

*실제 프로젝트 완료 후에는 분석 기간·데이터 건수·정제 결과·분류 지표·대표 발견을 실측 수치로 교체한다.*
