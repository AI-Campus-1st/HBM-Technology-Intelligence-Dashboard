## 필수 1. 이슈 키워드 추출의 정확도 표본 검수

### 왜 필요한가
- 가이드 3-1 기본 목표: "LLM으로 감성 분류 **및 핵심 이슈 추출**을 수행하고, 결과의 **정확도를 표본 검수로 확인**하였다"
- 가이드 6 유의사항: "LLM의 감성 분류와 **이슈 추출 결과**는 그대로 신뢰하지 않는다. 표본을 직접 검수하여 정확도를 확인하고 리포트에 기록한다"

### 지금 상태
| 항목 | 상태 |
|---|---|
| 키워드 추출 | 됨. `sent_v2`가 기사마다 `issue_keywords`를 낸다 (`outputs/reports/news_analysis_sent_v2.csv`, 385건, 예: `["HBM 시장 주도권", "HBM4 개발", "반도체 기술 경쟁"]`) |
| 감성 검수 | 됨. 50건 + 교차 25건, 4.5절 |
| **키워드 검수** | **안 됨.** 4.4절에는 상위 키워드 빈도만 있고, 7.1절에는 "빈도는 참고로만 사용"이라고만 있다. 맞는 키워드인지 사람이 본 기록이 없다 |

### 할 일
**① 검수 파일 만들기** — `data/labels/keyword_review_sent_v2.csv`
- 대상: 감성 검수 표본 중 김한승이 라벨한 **1~50행**(`data/labels/sentiment_review_sent_v1.csv`의 `news_id`). 기사를 이미 읽은 표본이라 빠르다.
- 열 제안:

  | 열 | 내용 |
  |---|---|
  | `news_id`, `title` | 표본에서 가져옴 |
  | `issue_keywords` | `news_analysis_sent_v2.csv`의 LLM 키워드 (JSON 목록 그대로) |
  | `kw_total` | 키워드 개수 |
  | `kw_correct` | 그중 **기사 본문에 실제로 나오는 이슈**인 개수 (사람 판정) |
  | `kw_core` | 기사의 **중심 이슈**를 키워드 중 하나라도 잡았으면 1, 아니면 0 |
  | `note` | 틀린 키워드와 이유 (예: 기사 밖 지식, 너무 일반적, 다른 기업 이야기) |
  | `labeler` | 김한승 |
- 주의: `news_id`는 문자열로 읽고 저장한다(감성 라벨 파일처럼 Excel 저장 시 깨지지 않게 맨 끝에 `key` 열을 두는 방식을 써도 된다. 7.5 '라벨 파일과 Excel').

**② 채점 기준 (판정 전에 정해 두기 — 7.6 교훈)**
- 맞음: 기사에 나온 사건·주제를 가리킨다. 표현이 달라도 같은 이슈면 맞음 ('대중 수출 통제' = '대중국 HBM 수출 규제').
- 틀림: 기사에 없는 내용, 기사 밖 지식으로 추론한 내용, 'HBM'·'반도체'처럼 너무 일반적이라 이슈가 아닌 것.
- 이 검수는 LLM 키워드를 보면서 판정하므로 감성처럼 블라인드가 아니다. 리포트에 그대로 적는다.

**③ 지표 계산**
- 키워드 정밀도 = Σ`kw_correct` / Σ`kw_total`
- 중심 이슈 포착률 = 평균(`kw_core`)
- 표본이 50건이라 신뢰구간(Wilson 95%)도 같이 적는다. `validate_sample.py`의 정확도 표처럼.
- 구현 방법은 자유. 코드로 하면 `src/llm/validate_sample.py`에 `keywords` 하위 명령(표본 파일 만들기·채점)을 더하고 `tests/test_validate_sample.py`에 테스트를 추가하는 것을 권한다. 결과는 `outputs/reports/keyword_eval_sent_v2.csv`.

**④ 리포트 반영** (숫자 나온 뒤)
| 위치 | 고칠 것 |
|---|---|
| 4.5 표본 검수 | 끝에 '이슈 키워드 검수' 소절: 표본·기준·정밀도·포착률·대표 오류 2~3개 |
| 4.7 한계 | 키워드 검수는 블라인드가 아니고 50건이라는 점 |
| 7.1 표 '이슈 키워드 표현 분산' 행 | '대응'·'남은 위험'에 검수 결과 반영 |
| 0.4 AI 결과의 신뢰도 표 | '이슈 키워드 추출' 행 추가 |
| 체크리스트 Day 4 | 키워드 검수 근거 추가 |
