## 4.2 프롬프트 설계 (`sent_v1`)

> 코드: `src/llm/prompts.py` (버전 기록은 파일 머리 주석)

- **기업별 감성:** 기사 하나를 SK하이닉스 관점·삼성전자 관점으로 **따로** 판정한다. 같은 기사가 한 기업엔 호재, 다른 기업엔 악재일 수 있어서다 (예: "삼성 HBM 인증 지연" → 삼성 부정, SK 중립 또는 긍정). 기사 전체 감성 하나로는 페르소나(반도체 애널리스트)의 비교 질문에 답할 수 없다.
- **라벨 4개:** 긍정 / 중립 / 부정 / 해당없음 (정의는 초안 v1.2 §5 C, 기준은 '해당 기업의 HBM 사업 관점'). '해당없음'을 따로 둬서 "등장하지 않음"과 "등장했지만 중립"을 구분한다.
- **판정 규칙 6개:** ① 두 기업 따로 ② 기사에 나온 사실·평가만 근거(기사 밖 지식·주가 전망 추론 금지) ③ 이름만 스치면 중립 ④ 약칭·인물(하이닉스·삼전·SK그룹 회장 발언) 처리 — 정규식 태깅이 놓치는 경우(3.1절 '최태원 SK회장')를 보완 ⑤ 호재·악재가 섞이면 중심 사건 기준, 어려우면 중립 ⑥ 이슈 키워드 1~5개(기업명 단독 금지)
- **출력:** JSON 하나 `{"sentiment_skh", "sentiment_sec", "issue_keywords"}`. API의 JSON 모드로 받고, 코드(`parse_response`)가 라벨 값·형식을 다시 검증한다. 틀리면 저장하지 않고 재시도한다.

## 4.3 실행과 재현성

- **재실행 안전:** 같은 프롬프트 버전으로 저장된 기사는 건너뛴다 → 중간에 끊겨도 다시 실행하면 남은 기사만 처리한다. 20건마다 DB에 저장한다. 버전을 올리면(`sent_v2`) 기존 결과를 지우지 않고 따로 저장해 v1·v2를 같은 표본으로 비교한다 (`news_analysis` 기본키 = 기사 + 프롬프트 버전).
- **실패 처리:** 응답 형식 오류·호출 실패는 최대 2번 재시도, 그래도 실패하면 실패 목록 CSV에 남긴다. 기사 5건이 **연속** 실패하면 남은 기사를 호출하지 않고 멈춘다 (아래 사례 이후 추가).
- **실행 중 문제와 해결 (2026-11-19):**
  1. `.env` 없음 → API 호출 전 중단 (비용 0).
  2. 20건 점검에서 20건 모두 `TypeError: Decompressor.decompress() got an unexpected keyword argument 'output_buffer_limit'`. 진단 결과 `urllib3` 2.8.0이 쓰는 인자를 오래된 `brotlicffi` 1.1.0.0이 지원하지 않는 패키지 호환 문제였다 (코드·프롬프트 문제 아님). `brotlicffi` 업그레이드로 해결. 이 과정에서 20건 × 3회 = 60회 호출이 응답 해제 단계에서 실패했다.
  3. 같은 오류로 호출만 반복하는 것을 막으려고 연속 실패 중단을 넣었다. 두 번째 실행에서는 5건 만에 멈춰 15건을 호출하지 않았다.
  4. 팀 패키지 버전을 requirements에 고정했다(#45, pandas 3.1.1 등). `brotlicffi`는 requirements에 없는 간접 의존성이라 고정 대상 추가를 논의 중이다.

## 4.5 표본 검수

> 코드: `src/llm/validate_sample.py` / 라벨: `data/labels/sentiment_review_sent_v1.csv` / 결과: `outputs/reports/sentiment_eval_sent_v1*.csv`, `sentiment_eval_sent_v2*.csv`

- **표본:** 100건, 층 = 분기 × 기업 그룹(v1 판정 기준 SK만·삼성만·둘 다·둘 다 해당없음), 층 크기 비례 배분(최대 나머지 방식), seed 42. **표본은 v1에서 한 번 뽑아 고정**하고, v2도 같은 표본·같은 사람 라벨로 채점한다.
- **블라인드:** 검수 파일에 LLM 판정을 넣지 않는다. 김한승 1~50행, 한도윤 1~25행(교차 검수)을 서로 보지 않고 판정했다. **51~100행은 시간 관계로 라벨하지 않았다** (표본 50건, 신뢰구간 폭 약 ±0.12).
- **지표:** 라벨이 불균형해 다수 라벨만 맞혀도 정확도가 높게 나오므로, 정확도와 함께 Macro-F1(라벨별 F1 단순 평균)·κ·라벨별 재현율·혼동행렬을 본다.
- **사람 라벨 수정 (1회):** 1차 채점 후 '기업이 등장하는데 해당없음'으로 표시한 칸(SK 6·삼성 3)을 김한승이 원문을 다시 보고 고쳤다 (정의: 해당없음 = 등장하지 않음). 재판정 중 삼성 3행도 중립 → 부정으로 바꿨다. 수정 전 점수도 함께 적는다.

| 기업 | 버전 | 정확도 (95% CI) | Macro-F1 | κ (LLM-사람) | LLM-교차 일치 (25건) |
|---|---|---|---:|---:|---:|
| SK하이닉스 | v1 · 라벨 수정 전 | 0.64 (0.50~0.76) | 0.62 | 0.52 | 0.68 |
| SK하이닉스 | v1 · 라벨 수정 후 | 0.70 (0.56~0.81) | 0.68 | 0.60 | 0.68 |
| SK하이닉스 | **v2** | **0.78 (0.65~0.87)** | **0.80** | **0.71** | **0.88** |
| 삼성전자 | v1 · 라벨 수정 전 | 0.84 (0.72~0.92) | 0.82 | 0.78 | 0.72 |
| 삼성전자 | v1 · 라벨 수정 후 | 0.88 (0.76~0.94) | 0.87 | 0.84 | 0.72 |
| 삼성전자 | **v2** | **0.88 (0.76~0.94)** | **0.87** | **0.83** | **0.84** |

- **사람끼리 일치도 (라벨 수정 후, 25건):** SK하이닉스 0.72 (κ 0.57), 삼성전자 0.68 (κ 0.57). v2와 교차 검수자의 일치율(0.88·0.84)이 사람끼리보다 높다. 감성 판정은 사람 사이에서도 갈리는 과제이므로 정확도를 '정답과의 일치'로만 읽지 않는다.
- **v2 라벨별:** '해당없음' F1이 두 기업 모두 1.00 (v1 SK 0.71). SK '부정' 재현율 0.33 → 0.67. 반면 SK '긍정' 정밀도 0.57 (예측 21건 중 정답 13) — v2가 긍정을 많이 낸다 (4.6절 ⑥).
- **채택:** 대시보드·SQL 04는 `sent_v2`를 쓴다. SK하이닉스는 모든 지표가 올랐고 삼성전자는 같다.
- **주의 — 낙관적 추정:** v2 규칙은 이 50건의 오류를 보고 만들었으므로, 같은 50건으로 잰 v2 점수는 실제보다 높게 나올 수 있다. 라벨하지 않은 51~100행 일부를 v2 확정 후 라벨하면 독립 검증이 된다 (후속 과제).

## 4.6 오류 유형

> v1 불일치(라벨 수정 전) SK 18건·삼성 8건을 하나씩 분류하고, v2에서 어떻게 바뀌었는지 확인했다. ①·②의 v2 결과는 라벨 수정 후 기준.

| 유형 | v1 건수 (SK / 삼성) | 내용 | 대응 → v2 결과 |
|---|---|---|---|
| ① 본문 잘림 | 5 / 4 | 기업이 긴 기사(2,900~4,400자) 뒤쪽에만 나와 v1이 '해당없음' | 본문 6,000자 → **9건 모두 '해당없음' 아님** (그중 SK 3·삼성 3건 정답) |
| ② 업계 공통 악재를 중립으로 | 3 / 0 | 미국 수출 규제·정치 리스크로 'K반도체' 전체가 타격받는 기사에서 사람 '부정', v1 '중립' | 규칙 7 → 3건 중 2건 정답 (29행 '로이터 "삼성전자가 영향 받을 것"'은 SK 영향 서술이 없어 v2도 중립) |
| ③ 사람 라벨 '해당없음' 정의 차이 | 6 / 3 | 기업이 등장하는데 사람이 '해당없음' | 사람 라벨 수정 (4.5절) |
| ④ 긍정 vs 중립 경계 | 3 / 1 | 기업 행사·발언 기사에서 LLM·교차 검수자 '긍정', 김한승 '중립' | v2에서도 남음 (8·10행). 사람 기준이 갈리는 유형 |
| ⑤ 기타 | 2 / 2 | 예: 'HBM 1년 늦은 삼성전자, 실적도 SK하이닉스 절반 이하'를 사람 SK '부정', LLM '긍정' | 남음. 사람 라벨 재확인 후보 |
| ⑥ **v2 새 오류: 규칙 7 과적용** | — | '수출 통제, 삼성·하이닉스 영향 제한적' 기사(33·34·36행)를 v2가 긍정·부정으로 판정, 사람은 중립 | v3 후보: "영향이 제한적·없다는 서술은 중립" |

- ①·②는 프롬프트 설계로 고칠 수 있는 오류였고 v2에서 대부분 고쳐졌다. ①은 20건 점검에서 의심한 유형이 수치로 확인된 경우다.
- ③·④는 LLM이 아니라 사람 라벨의 일관성 문제다. ⑥은 규칙을 추가하면 다른 곳에서 새 오류가 생길 수 있다는 사례로, 정확도가 오른 버전에서도 오류 목록을 다시 확인해야 한다.

- 보도 논조 ≠ 실제 사업 성과·시장 점유율 (초안 §9.3).
- 분류 대상은 정규식 태깅(HBM 핵심·관련)을 거친 기사라, 태깅이 놓친 HBM 기사(추정 재현율 0.85)는 감성 분석에서도 빠진다.
- v2도 본문 앞 6,000자까지만 본다 (기사 98.2%는 전문).
