## 4.2 프롬프트 설계 (`sent_v1`)

> 코드: `src/llm/prompts.py` (버전 기록은 파일 머리 주석)

- **기업별 감성:** 기사 하나를 SK하이닉스 관점·삼성전자 관점으로 **따로** 판정한다. 같은 기사가 한 기업엔 호재, 다른 기업엔 악재일 수 있어서다 (예: "삼성 HBM 인증 지연" → 삼성 부정, SK 중립 또는 긍정). 기사 전체 감성 하나로는 페르소나(반도체 애널리스트)의 비교 질문에 답할 수 없다.
- **라벨 4개:** 긍정 / 중립 / 부정 / 해당없음 (정의는 초안 v1.2 §5 C, 기준은 '해당 기업의 HBM 사업 관점'). '해당없음'을 따로 둬서 "등장하지 않음"과 "등장했지만 중립"을 구분한다.
- **판정 규칙 6개:** ① 두 기업 따로 ② 기사에 나온 사실·평가만 근거(기사 밖 지식·주가 전망 추론 금지) ③ 이름만 스치면 중립 ④ 약칭·인물(하이닉스·삼전·SK그룹 회장 발언) 처리 — 정규식 태깅이 놓치는 경우(3.1절 '최태원 SK회장')를 보완 ⑤ 호재·악재가 섞이면 중심 사건 기준, 어려우면 중립 ⑥ 이슈 키워드 1~5개(기업명 단독 금지)
- **출력:** JSON 하나 `{"sentiment_skh", "sentiment_sec", "issue_keywords"}`. API의 JSON 모드로 받고, 코드(`parse_response`)가 라벨 값·형식을 다시 검증한다. 틀리면 저장하지 않고 재시도한다.

## 4.3 실행과 재현성

- **재실행 안전:** 같은 프롬프트 버전으로 저장된 기사는 건너뛴다 → 중간에 끊겨도 다시 실행하면 남은 기사만 처리한다. 20건마다 DB에 저장한다. 버전을 올리면(`sent_v2`) 기존 결과를 지우지 않고 따로 저장해 v1·v2를 같은 표본으로 비교한다 (`news_analysis` 기본키 = 기사 + 프롬프트 버전).
- **실패 처리:** 응답 형식 오류·호출 실패는 최대 2번 재시도, 그래도 실패하면 실패 목록 CSV에 남긴다. 기사 5건이 **연속** 실패하면 남은 기사를 호출하지 않고 멈춘다 (아래 사례 이후 추가).
- **실행 중 문제와 해결 (2026-11-19):**
  1. `.env` 없음 → API 호출 전 중단 (비용 0).
  2. 20건 점검에서 20건 모두 `TypeError: Decompressor.decompress() got an unexpected keyword argument 'output_buffer_limit'`. 진단 결과 `urllib3` 2.8.0이 쓰는 인자를 오래된 `brotlicffi` 1.1.0.0이 지원하지 않는 패키지 호환 문제였다 (코드·프롬프트 문제 아님). `brotlicffi` 업그레이드로 해결. 이 과정에서 20건 × 3회 = 60회 호출이 응답 해제 단계에서 실패했다.
  3. 같은 오류로 호출만 반복하는 것을 막으려고 연속 실패 중단을 넣었다. 두 번째 실행에서는 5건 만에 멈춰 15건을 호출하지 않았다.
  4. 팀 패키지 버전을 requirements에 고정했다(#45, pandas 3.1.1 등). `brotlicffi`는 requirements에 없는 간접 의존성이라 고정 대상 추가를 논의 중이다.

## 4.5 표본 검수

> 코드: `src/llm/validate_sample.py` / 라벨: `data/labels/sentiment_review_sent_v1.csv` / 결과: `outputs/reports/sentiment_eval_sent_v1*.csv`

- **표본:** 100건, 층 = 분기 × 기업 그룹(LLM 판정 기준 SK만·삼성만·둘 다·둘 다 해당없음), 층 크기 비례 배분(최대 나머지 방식), seed 42. '둘 다 해당없음'도 표본에 들어가 놓친 언급을 확인한다.
- **블라인드:** 검수 파일에 LLM 판정을 넣지 않는다. 김한승이 100건 전부, 한도윤이 앞 25건을 서로의 판정을 보지 않고 판정한다 (교차 검수).
- **지표:** 정확도만 내지 않는다. 라벨이 불균형(중립·해당없음이 많을 것으로 예상)해 다수 라벨만 맞혀도 정확도가 높게 나오기 때문이다. 기업별 정확도(Wilson 95% CI)·**Macro-F1**(라벨별 F1 단순 평균)·LLM-사람 κ, 교차 검수 일치율·κ, 라벨별 정밀도·재현율, 혼동행렬을 함께 본다.
- **중간 결과 (2026-11-19, 김한승 50건 = 1~50행, 교차 검수 한도윤 25건 = 1~25행):**

| 기업 | n | 정확도 (95% CI) | Macro-F1 | κ (LLM-사람) | 교차 일치율 | κ (사람-사람) |
|---|---:|---|---:|---:|---:|---:|
| SK하이닉스 | 50 | 0.64 (0.50~0.76) | 0.62 | 0.52 | 0.64 | 0.50 |

  - SK하이닉스 '부정' 재현율 0.33 (사람 부정 12건 중 LLM 4건) — 가장 약한 지점.

## 4.6 오류 유형

| 유형 | 건수 (SK / 삼성) | 내용 | 대응 |
|---|---|---|---|
| ① 본문 잘림 | 4 / 3 | 기업이 본문 뒤쪽에 1~3번 나오는 긴 기사(2,900~4,400자)를 LLM이 '해당없음'으로 판정 — 앞 1,500자만 넣은 영향 | v2: 입력 본문 확대 |
| ② 업계 공통 악재를 중립으로 | 4 / 0 | 미국 수출 규제·정치 리스크로 'K반도체' 전체가 타격받는 기사에서 사람은 '부정', LLM은 '중립' (규칙 3·5의 보수적 판정) | v2: "기업이 명시된 업계 공통 악재·호재는 그 기업에도 적용" 규칙 추가 |
| ③ 사람 라벨의 '해당없음' 정의 차이 | 5~6 / 2~3 | 기업이 등장(제목 포함 1건)하는데 사람이 '해당없음' — 정의상 '중립' 이상. 교차 검수자는 3건 중 3건을 LLM과 같게 판정 | 김한승 라벨 재확인 (SK 3·4·7·12·22·39행, 삼성 1·4·12행) |
| ④ 긍정 vs 중립 경계 | 3 / 1 | 기업 행사·발언 기사에서 LLM·교차 검수자는 '긍정', 김한승은 '중립' | 사람 기준 정리 (사람-사람 불일치와 같은 유형) |
| ⑤ 기타 | 2 / 2 | 예: 'HBM 1년 늦은 삼성전자, 실적도 SK하이닉스 절반 이하'를 사람은 SK '부정'(라벨 확인 필요), '트럼프 2기 K반도체 먹구름'을 LLM은 SK '긍정' | 개별 확인 |

- ①은 프롬프트 설계(본문 1,500자) 가정이 틀린 경우로, 20건 점검에서 의심한 유형이 수치로 확인됐다.
- ③·④는 LLM 오류가 아니라 **사람 라벨의 일관성** 문제다. 라벨 정의('해당없음' = 등장하지 않음)를 다시 확인한 뒤 수정하면 정확도가 달라질 수 있어, 수정 전·후를 모두 기록한다.
