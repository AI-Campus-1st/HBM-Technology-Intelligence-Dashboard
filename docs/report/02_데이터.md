### 데이터 교체 경위 (회고 참고)

처음 받은 파일은 AI반도체 묶음(120,057건, 2021-10 ~ 2026-10, 키워드 `AI 반도체`)이었고 이 데이터로 기획 초안 v1.1을 썼다. 2026-11-13에 제공 데이터가 반도체 묶음(7,177건)으로 바뀌었다. 영향은 다음과 같다.

- 규모가 약 1/17로 줄어 HBM 제목 기사가 분기당 1~46건 → 급증 탐지를 주 단위에서 **월 단위**로 바꿨다.
- 가이드의 이슈 카테고리 구조를 가진 데이터가 되어 '카테고리' 필터를 그대로 쓸 수 있게 됐다.
- HBM 제목 기사 205건 중 90건이 `반도체 수출 통제` 키워드로 수집되었다. HBM 이슈가 규제 사건 위주로 보일 수 있어 카테고리별로 나눠 해석한다.
- 분석 기간을 2023-01-01 ~ 2026-09-30에서 2023-10-19 ~ 2026-10-19로 바꿨다 (`config.py`).

### 적재 과정

`python -m src.news.load_news` (`src/news/load_news.py`)

1. `config.NEWS_CSV`만 읽는다 (폴더에 다른 CSV가 있어도 무시).
2. 컬럼 변환: 제목·본문·URL·발행일·매체명·수집키워드 → `news` 테이블 컬럼.
3. 수집 키워드를 카테고리로 바꾸고 정해진 순서로 저장한다. 매핑에 없는 키워드가 나오면 멈춘다.
4. `db.write_table(mode="replace")`로 저장해 다시 실행해도 결과가 같다.

**적재 결과:** 7,177건, FK 위반 0건, `news` 기본키 지문 `f7e3236fe557` (두 사람 DB 비교용, `python -m src.common.db --check`).

## 2.4 통합 스키마

SQLite(`data/db/hbm.db`), 정의는 `src/common/schema.py`·`docs/schema.md` v1.2. 두 사람이 각자 같은 코드와 입력으로 DB를 만들고 `--check`로 맞춰 본다 (`docs/conventions.md` §5).

| 테이블 | 담당 | 내용 |
| --- | --- | --- |
| `news` | 김한승 | 뉴스 원본 + 카테고리 + 중복 표시 |
| `news_tag` | 김한승 | 정규표현식 기술·기업 태그와 관련도 등급 (기사당 여러 행) |
| `news_analysis` | 김한승 | LLM 기업별 감성·이슈 키워드 (프롬프트 버전별) |
| `issues` | 김한승 | 월 단위 HBM 급증 구간 |
| `disclosure` | 한도윤 | 공시 목록·본문 |
| `issue_evidence` | 공동 | 급증 구간과 기사·공시의 연결 (자동 연결은 후보) |

**설계 판단:** 규칙 태그(`news_tag`)와 LLM 결과(`news_analysis`)를 분리했다. 태그는 전체 기사에 비용 없이 붙이고, LLM은 HBM 기사에만 비용을 들여 돌리므로 범위와 버전 관리가 다르다.

## 2.5 HBM 기사 선정 (태깅)

자세한 검수 과정은 4장에서 다루고, 여기서는 분석 대상을 정한 기준만 적는다.

- 규칙: `src/news/tagging.py` `regex_v3` — 제목 포함이면 **핵심**, 본문 5회 이상이면 **관련**, 1~4회면 **언급**
- 분석 대상: HBM 핵심+관련 386건 (제목 중복 제외). 표본 검수 기준 추정 정밀도 0.95, 재현율 0.86
- 기업 태그(SK하이닉스·삼성전자)는 이름만 나열된 기사가 많아 **HBM 핵심·관련 기사 안에서만** 집계한다
- ⚠️ 검수 라벨은 1차 자동 판정이며 사람 검수 후 확정 수치로 바꾼다
