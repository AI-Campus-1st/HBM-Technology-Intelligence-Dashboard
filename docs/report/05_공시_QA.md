# 5. 공시 QA

> 담당: 공동 (장별 파일이라 동시에 써도 충돌이 적다)

## 5.1 청킹 (한도윤, Day 3)

> 코드: `src/rag/chunking.py` (`python -m src.rag.chunking`) / 결과: `data/processed/disclosure_chunks.jsonl`(git에 올리지 않음), 요약 `outputs/reports/disclosure_chunk_summary.csv`

### 대상과 단위
- **대상:** DB `disclosure`에서 원문을 확보했고 `rag_target=1`인 공시 202건. RAG 대상 기준은 DB에 적힌 값을 그대로 따르므로, 기준이 바뀌면 다시 실행만 하면 된다.
- **정기보고서(A):** 본문 전체(건당 20만~70만 자, 대부분 재무제표)를 쓰지 않는다. 3.3절의 사업·제품·투자·연구개발 섹션만 쓴다. 삼성전자 연구개발실적(상세)은 TV·모바일 같은 DX 부문이 대부분이어서 **DS 부문 부분만** 남긴다.
- **그 밖의 공시(B·D·I·J):** 본문 전체를 섹션 '본문' 하나로 본다. 섹션 성격에는 공시명으로 정한 공시 성격(투자·설비, 풍문·해명 등, 3.2절)을 넣는다.

### 자르는 방법
- **표 행 묶기:** DART 표는 텍스트로 바뀌면 칸마다 줄이 나뉜다. 30자 이하 줄이 이어지면 ` | `로 묶는다. 예: `연구개발비용 합계 | 6,732,527 | 4,954,447 | …`. 항목 이름과 값이 다른 청크로 갈라지지 않게 하기 위해서다. '가.', '(1)', '2. ' 같은 소제목은 묶지 않는다.
- **크기:** 1,000자, 앞뒤 청크 겹침 150자. LangChain `RecursiveCharacterTextSplitter`로 줄 → 표 칸(` | `) → 문장 → 공백 순서로 자를 곳을 찾는다. 30자 미만 조각은 버린다.
- **머리말:** 청크 앞에 `[기업 | 공시명 | 제출일 | 섹션]`을 붙인다. 본문에 회사명이나 시점이 없어도 "삼성전자 2025년 시설투자" 같은 질문에 검색되게 하려는 것이다.
- **메타데이터:** `chunk_id`(`<rcept_no>_<섹션 순번>_<청크 순번>`, 다시 실행해도 같다), `rcept_no`, `corp_code`, `corp_name`, `report_nm`, `rcept_dt`, `pblntf_ty`, `url`, `section`, `section_type`, `chunk_index`, `n_chars`, `has_hbm`. 답변에 근거로 표시할 공시명·제출일·링크와 기업 필터에 필요한 값이 모두 들어 있다.
