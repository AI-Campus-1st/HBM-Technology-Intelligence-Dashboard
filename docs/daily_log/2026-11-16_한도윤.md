## 내린 판단과 근거 (리포트·회고용)

| 판단 | 근거 |
| --- | --- |
| DB 파일은 주고받지 않고 각자 재생성 | 파일을 주고받으면 서로 덮어써 작업이 사라지기 쉽고 최신본을 알 수 없다. 같은 코드 + 같은 입력이면 같은 DB가 나오고 `--check`로 확인할 수 있다 |
| D 지분공시는 위임장 참고서류만 | 4,256건 중 소유상황보고서 4,161건(삼성전자 3,530건). 넣으면 공시 건수 추이가 임원 주식 거래 추이가 된다. 표본 키워드 확인: 소유상황·대량보유 각 20건 중 0건, 위임장 참고서류 17건 중 10건 |
| J 공정위공시는 원문을 받은 뒤 본문으로 거름 | 같은 공시명 아래 "신규 FAB 구축" 4.0조 원 매입(SK에코플랜트)과 항공기·퇴직연금·급식 거래가 섞여 있어 공시명으로는 못 거른다 |
| J 키워드에서 '반도체'·'장비' 제외 | 207건 전수 확인 결과 대규모기업집단현황공시의 계열사 업종 목록에만 걸렸다. 대규모기업집단현황공시·부동산임대는 공시명으로 제외 → RAG 대상 29건 |
| I 거래소공시는 공시명으로 거름 | 배당·IR 안내·지분 변동 등은 이름만으로 내용이 정해져 있다. '배당'이 들어간 기타경영사항도 제외 |
| 정정공시는 최종본만 (`last_reprt_at=Y`) | 같은 공시가 두 번 세어지거나 RAG에 옛 버전이 섞이는 것을 막는다 |
| `text_status`와 `rag_target`을 따로 둠 | J는 원문을 받았지만(확보) RAG에는 안 쓰는 경우가 있어 하나의 상태로 표현할 수 없다 |
| 원문은 본 문서만, 첨부 제외 | 감사보고서 등 첨부는 분량이 크고 정기보고서 본문과 겹친다 |
| D 위임장 참고서류 같은 해 2건은 둘 다 둠 | 중복이 아니라 회사 문서(3만~8만 자)와 전자위임장 플랫폼 등 다른 권유자의 문서(3,600~8,000자)였다 |
